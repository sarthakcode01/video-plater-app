# Mobile Movie & Video Player — Engineering Architecture & Implementation Plan

## 1. Project Overview & Core Objectives
The objective is to build a local mobile movie and video player in **React Native (Expo)** capable of scanning device storage and playing downloaded movies and gallery videos with advanced playback controls.

### Core Functional Requirements:
1. **Local Movie & Gallery Discovery:** Automatically scan device folders to index `.mp4`, `.mkv`, and `.mov` video files.
2. **YouTube-Style Double-Tap Seeking:** Double-tapping the left or right sides of the screen skips backward or forward by 5 or 10 seconds, paired with visual ripple animations and dedicated on-screen skip buttons.
3. **Interactive Timeline Scrubber:** A responsive progress bar that allows users to either drag the thumb or tap directly on any point along the timeline to jump to that exact timestamp.
4. **Preset Playback Speeds:** A speed controller allowing users to play videos at `1.0x`, `1.25x`, `1.5x`, `1.75x`, and `2.0x`.
5. **Instagram-Style Hold for 2x Speed:** Pressing and holding anywhere on the video screen temporarily boosts playback speed to `2.0x` for as long as the finger remains pressed, immediately reverting to the user's previously selected speed upon release.
6. **Embedded Multi-Audio & Subtitle Detection:** Automatically detect all audio tracks (e.g., Dual Audio Hindi/English) and embedded subtitle tracks packed inside the movie file and allow seamless switching during playback.
7. **Cloud Compilation Only:** Use **Expo Application Services (EAS Build)** to compile native dependencies in the cloud without requiring local Android Studio or Xcode builds.

## 2. Technical Stack & Library Decisions

| Layer | Selected Tool / Library | Architectural Justification |
| :--- | :--- | :--- |
| **Core Framework** | Expo SDK + `expo-dev-client` | Allows integrating custom native video decoders while keeping the Expo managed workflow and fast refresh. |
| **Cloud Build Pipeline** | EAS Build (Expo Cloud) | Compiles the custom native Android APK and iOS builds on Expo's cloud servers, removing the need for local native toolchains. |
| **Video Engine** | `react-native-video` (v6+) | Uses Google's native Media3/ExoPlayer on Android and AVPlayer on iOS, which is mandatory for reading embedded `.mkv`/`.mp4` audio streams and subtitle tracks. |
| **Storage & Gallery** | `expo-media-library` | Handles runtime OS media permissions and queries the device file system for video files, durations, and metadata. |
| **Gesture Engine** | `react-native-gesture-handler` | Manages complex multi-touch priorities (Single Tap vs. Double Tap vs. Long Press) on the native UI thread without lag. |
| **Timeline Scrubber** | `@react-native-community/slider` | Provides smooth dragging and direct tap-to-seek functionality along the video timeline. |
| **Orientation Control** | `expo-screen-orientation` | Locks the screen into landscape mode when entering fullscreen movie playback and restores portrait mode on exit. |

## 3. Phase-Wise Implementation Guide

### Phase 1: Project Setup & EAS Cloud Build Workflow
Because standard Expo Go does not include the native media decoders required to extract embedded audio and subtitle streams from movie files, the first phase establishes a custom development client compiled in the cloud.

* **Step 1.1 — Initialize Expo Workspace:** Create the base Expo project and install the core packages for video playback, media library access, gestures, sliders, and screen orientation.
* **Step 1.2 — Configure Native Plugins:** Register `expo-media-library` and `react-native-video` inside the Expo configuration so that the cloud builder automatically injects Android (`READ_MEDIA_VIDEO`) and iOS (`NSPhotoLibraryUsageDescription`) storage permissions into the native manifests.
* **Step 1.3 — Set Up EAS Cloud Profiles:** Configure the EAS build configuration to generate an installable internal Android `.apk` (or iOS simulator/device build) with the development client enabled.
* **Step 1.4 — Trigger Cloud Compilation:** Submit the build job to Expo Cloud. Once finished, download and install this custom client app onto your physical phone. All subsequent phases will run directly inside this installed app via standard Expo wireless bundler reloads.

---

### Phase 2: Gallery Scanner & Movie Library Screen
This phase focuses on requesting operating system permissions, scanning the device for movie files, and displaying them in a clean library interface.

* **Step 2.1 — OS Permission Handshake:** When the app launches, check and request media library permissions. Handle all three permission states: Full Access, Limited Access (where the user selects specific videos on Android 14+ or iOS), and Denied Access (displaying a prompt guiding the user to system settings).
* **Step 2.2 — Video Asset Indexing:** Query the device storage filtered strictly to video media types. Sort the results by creation date or filename, and retrieve each file's local URI, duration, resolution, and title.
* **Step 2.3 — Pagination & Performance:** Since a device may hold hundreds of gallery videos and heavy movie files, load assets in batches (e.g., 50 items per batch) as the user scrolls to prevent memory spikes.
* **Step 2.4 — Library Grid/List UI:** Display the scanned videos with their thumbnail preview, formatted duration badge (`HH:MM:SS`), and file title. Tapping any video passes its local file URI and metadata to the Player Screen.

---

### Phase 3: Core Video Player & Interactive Timeline Scrubber
This phase builds the custom player view and timeline synchronization mechanism.

* **Step 3.1 — Native Controls Suppression:** Mount the video engine with native default controls turned off so that custom gestures and custom overlays have full control over the screen.
* **Step 3.2 — Playback State Synchronization:** Track real-time player states including whether the video is playing, buffering, its current playback timestamp, and total video duration.
* **Step 3.3 — Scrubbing & Tap-to-Seek Logic:** Connect the timeline slider bar to the video's current timestamp and total duration.
  * **Anti-Jitter Lock:** When the user touches or drags the timeline bar, temporarily pause automatic progress updates from the video engine so the slider thumb does not jump back and forth under their finger.
  * **Instant Seek Execution:** As soon as the user taps a specific point on the timeline or releases their drag, command the video engine to jump to that exact second and resume normal progress tracking.
* **Step 3.4 — On-Screen Seek Buttons:** Place dedicated `-10s` (or `-5s`) and `+10s` (or `+5s`) buttons in the center control bar that calculate the new timestamp (clamped between `0` and the total video duration) and jump immediately.

---

### Phase 4: Gesture Architecture (YouTube Double-Tap & Instagram Hold-to-2x)
To support single tap, double tap, and press-and-hold on the same screen without gestures colliding, this phase establishes a strict gesture priority hierarchy.

* **Step 4.1 — Screen Zone Partitioning:** Divide the invisible touch layer over the video into three vertical zones:
  * **Left Zone (Left 40% of screen width):** Dedicated to backward double-tap seeking.
  * **Center Zone (Middle 20% of screen width):** Dedicated to general screen taps.
  * **Right Zone (Right 40% of screen width):** Dedicated to forward double-tap seeking.
* **Step 4.2 — YouTube-Style Double-Tap Seek:** Configure a double-tap recognizer on the left and right zones. When a double-tap occurs in the left zone, rewind by 10 seconds and show a backward visual indicator. When a double-tap occurs in the right zone, fast-forward by 10 seconds and show a forward visual indicator. Multiple rapid taps should accumulate the seek time smoothly.
* **Step 4.3 — Exclusive Single-Tap UI Toggle:** Pair the single-tap recognizer with the double-tap recognizer in an exclusive relationship. When the user taps once, the system waits roughly 200 milliseconds to confirm a second tap isn't coming; once confirmed, it toggles the visibility of the player control overlay.
* **Step 4.4 — Preset Playback Speeds:** Maintain a base speed state (`1.0x`, `1.25x`, `1.5x`, `1.75x`, `2.0x`) selectable via an on-screen speed menu.
* **Step 4.5 — Instagram-Style Hold for 2x Speed:** Attach a long-press recognizer across the video touch surface that triggers after holding the screen for 250–300 milliseconds:
  * **On Hold Start:** Activate a temporary override flag that forces the video engine's playback speed to `2.0x`, hide the main controls so the view is unobstructed, and display a small `2x Speed >>` badge at the top of the screen.
  * **On Finger Release:** Immediately clear the override flag so the video engine seamlessly drops back to whatever preset speed the user had active before holding (for example, returning to `1.25x` or `1.0x`).

---

### Phase 5: Embedded Audio & Subtitle Track Detection and Switching
Movies (especially `.mkv` and multi-track `.mp4` files) contain internal metadata tables listing all packaged audio languages and subtitle streams.

* **Step 5.1 — Stream Metadata Extraction:** When a movie finishes initializing (`onLoad`), inspect the payload returned by the native player engine to extract the array of available audio tracks and the array of embedded text/subtitle tracks.
* **Step 5.2 — Track Identification & Labeling:** Format the extracted track data for the user interface using each stream's language code (e.g., `en`, `hi`, `ja`), track title (e.g., `English 5.1`, `Hindi Dub`, `English [Forced]`), and track index number.
* **Step 5.3 — Real-Time Audio Track Switching:** Build an Audio Selector menu. When the user picks a different language or audio stream, pass that track's index to the video player's selected audio prop. The native decoder switches the audio stream on the fly without restarting the movie.
* **Step 5.4 — Real-Time Embedded Subtitle Switching:** Build a Subtitle Selector menu that includes an "Off / Disabled" option alongside all detected embedded subtitle tracks. Selecting a track passes its index to the player's selected text track prop, rendering the embedded subtitles directly over the video frame.

---

### Phase 6: Fullscreen Orientation, Auto-Hide Controls & Edge Cases
The final phase refines the movie-watching experience to match commercial streaming and local media apps.

* **Step 6.1 — Landscape Fullscreen Locking:** When the user opens a movie or taps the fullscreen toggle, lock the device orientation to landscape mode and hide the operating system status bar and bottom navigation bar for an edge-to-edge viewing experience. Unlock back to portrait mode when exiting the player.
* **Step 6.2 — Auto-Hiding Control Timer:** Whenever the control overlay is visible during active playback, run a 3.5-second inactivity countdown. If the user does not tap, scrub, or open a menu before the timer expires, automatically fade out the controls. Any interaction resets the timer.
* **Step 6.3 — App Background & Interruption Handling:** Listen for operating system app state changes (such as incoming phone calls, locking the phone screen, or switching apps) and automatically pause the movie so the user does not lose their place.
* **Step 6.4 — Unsupported Codec Fallback Handling:** Add error listeners to catch corrupted video files or unsupported proprietary audio codecs, displaying a clear message to the user if a specific stream cannot be decoded by the device hardware.
